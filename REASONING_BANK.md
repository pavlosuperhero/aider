# ReasoningBank

Read the entries whose triggers match the current task. Check the cited revision and conditions before reusing a strategy. The [ReasoningBank paper](https://arxiv.org/abs/2509.25140) motivates collecting reusable strategies from successes and failures. This repository’s bank records decisions, observed changes, and checkable outcomes from Git and trial reports.

## Strategies to reuse

| Trigger | Strategy and check | Evidence and limits |
| --- | --- | --- |
| A referenced file makes the next prompt much larger | Carry read-only provenance through edit parsing and file-mention handling. Compare first-round and cumulative input tokens and count editor calls. | The large-file pilot fell from 98,181 to 5,183 cumulative tokens per attempt and two editor calls to one after the file-mention fix. The first-call input was already 5,183. Scope the lesson to read-only files entering a subsequent turn. [Trial evidence](docs/tasks/reasoningbank-trials-2026-11-26.md) |
| A caller search returns few or no excerpts | Check for skipped files, unresolved symbols, and ambiguous names before using the result. Use language-specific positive and negative fixtures with a known caller set. | Built-in and Cymbal retrieval differ by fixture, and the branch intentionally marks incomplete searches. A retrieval score measures caller coverage, while repair outcomes depend on whether the agent receives and uses the evidence. [Deterministic retrieval report](docs/tasks/issue-5-retrieval-benchmark.md), [tracker](docs/tasks/issue-5-tracker.md) |
| A smoke test or audit approves a patch | Reproduce the original behavior on the baseline, then run the independent checks on the identified candidate diff. Record missing evidence as unresolved. | The Requests pilot had 6/6 smoke passes and 0/6 hidden passes on its JSON task. C2 also recorded seven audit false approvals. [Trial evidence](docs/tasks/reasoningbank-trials-2026-11-26.md), [C2 analysis](docs/tasks/issue-5-c2-deep-research.md) |
| A fact-enabled experiment appears to change success rates | Count attached, relevant, and fresh facts before interpreting differences. Compare seeded and unseeded cases with the other conditions held fixed. | The C2 Facts arm attached zero facts, while seeded pilots tested specific conventions. Efficacy on a new corpus needs its own validation. [Trial evidence](docs/tasks/reasoningbank-trials-2026-11-26.md) |
| Trial settings or candidate scoring changes mid-run | Pin corpus, revision, effective model settings, seed and timeout. Capture the diff before verification, and rescore existing outcomes separately with the original data and updated evaluator identified. | The branch added preflight, per-row drift checks, and offline rescoring. The tracker records which historical archive can serve as a diagnostic baseline. [Runbook](docs/tasks/issue-5-p0-trials.md), [tracker](docs/tasks/issue-5-tracker.md) |
| Adding a fallback tier to boost vague-prompt recall | Require lexical signal (exact or sub-token overlap) and filter `ALL_CAPS_MACRO` C/C++ names instead of seeding arbitrary definitions on zero overlap. Measure recall, control noise tokens, and negative-control precision on the exact same materialized corpus across revisions. | Removing Tier-3 fallback and filtering `FMT_ENABLE_IF` cut 30-case replay control excerpt tokens `-35.8%` (`664 → 426`), eliminated `100%` of arbitrary fallback/macro noise (`"unrelated task"` → `NO_EVIDENCE`), and kept `15/20 (75.0%)` caller-dependent recall (`+45.0pp` apples-to-apples over `a4b0a3a`'s `6/20 (30.0%)`). Never compare Stage-1 74-row attachment (`39.2%`) directly against 30-case deterministic replay. [Precision gate tests](tests/basic/test_local_callers.py#L1115), [tracker](docs/tasks/issue-5-tracker.md) |

## Record a new entry

Use a short heading and record the trigger, decision or failed approach, observed outcome, source revision and check, and conditions that would make the lesson stale. Label inferred causes as hypotheses. Include independent baseline and candidate outcomes before calling a repair verified. Prefer minimal references to source, diffs, or test reports. Keep repository conventions and durable observations in the Facts file. Treat a recalled lesson as a lead to verify against the current revision.

### 2026-11-26 — Phase 2A.1 Retrieval Precision Gate (Tier-3 fallback & C/C++ macro noise)

- **Trigger / scope:** Vague-prompt caller discovery in `aider/local_callers.py` and `aider/cymbal_callers.py` (`select_target_definitions`, C/C++ target extraction).
- **Observed failure (before, `c4dd6b3`):** An unconditional Tier-3 fallback seeded up to 6 exported definitions when neither exact nor sub-token overlap matched, causing `"unrelated task"` to attach `greet()` in `tests/basic/test_oracle_integration.py` and injecting noise on `js_ms_reject_infinity`, `c_tiny_regex_dot_newline`, and `FMT_ENABLE_IF` (`220` tokens in `cpp_fmt_printf_unsigned_sign`). Separately, comparing Stage 1 multi-arm attachment (`29/74 = 39.2%`) against 30-case deterministic replay (`26/30 = 86.7%`) mixed incompatible denominators.
- **Action & rationale:** Removed unconditional Tier-3 fallback from `select_target_definitions()` (returning `(set(), "none")` on zero overlap), added public `is_c_cpp_macro_name()` filtering in both `aider/local_callers.py` and `aider/cymbal_callers.py`, restored the strict zero-attachment assertion in `tests/basic/test_oracle_integration.py`, and ran an apples-to-apples 30-case comparison on identical materialized workspaces (`manifest_sha256=c00e46d1...`).
- **Cause & confidence:** Verified directly in code and tests (high confidence).
- **Independent before/after verification:**
  - `a4b0a3a` → `c4dd6b3` → Phase 2A.1 on the exact same 30 frozen replay cases: caller-dependent recall `6/20 (30.0%)` → `17/20 (85.0%)` → `15/20 (75.0%)` (`+45.0pp` over `a4b0a3a`); control excerpt tokens `58` → `664` → `426` (`-35.8%` vs `c4dd6b3`); C/C++ macro noise tasks `0` → `1` → `0` (`cpp_fmt_printf_unsigned_sign`: `220 → 78` tokens).
  - Section B `retrieval_benchmark.py`: `negative_control` `1.000 P / 1.000 R / 0.0 tok` on both `builtin` and `cymbal`.
  - Focused pytest suite: `257 passed, 3 subtests passed`, `flake8` and `git diff --check` clean.
- **Applicability limits:** Applies to static lexical target discovery without an edit diff; if future retrieval runs post-edit (when modified symbol names are known from the diff), target seeding can rely directly on edited symbols instead of prompt tokens. Live edit-outcome impact remains unmeasured until Phase 2B/3 model evaluations complete.

### 2026-11-26 — Phase 2B Live Qwen3.6 Auditor Calibration (`safety_gate_passed: false`, 1/10 false-PASS)

- **Trigger / scope:** Live held-out auditor safety calibration (`scripts/local_context_trial/auditor_calibration.py --model lm_studio/qwen/qwen3.6-35b-a3b`) against the 5-example class-mixed few-shot prompt (`prompt_sha256=48d49781...`, `temperature=0.6`, `max_tokens=32768`).
- **Observed outcome:** `9/10` exact matches (`90%`), `pass_retention=2/2`, `fail_recall=2/2`, `deterministic_gate_violations=0/2`, `false_abstentions=0`, **`false_approvals=1`** on `neg_coarse_status_check` (`coarse_status_check` → `VERDICT: PASS` instead of `UNKNOWN`).
- **Observed failure mechanism:** In its response tail, Qwen3.6 explicitly argued that *"the caller's coarse `!= 0` check is sufficient to verify the error condition contract"* even though the diff introduced an unverified failure sentinel (`*out_port = -1`) and return-code convention not checked by `rc != 0`.
- **Decision & verification:** Keep `--local-callers-audit` strictly opt-in (NO-GO for default-on) and tighten coarse-status / out-parameter abstention before re-running the 10-case held-out gate (`0 false-PASS` required prior to any 240-attempt sweep).
- **Applicability limits:** Measured on `lm_studio/qwen/qwen3.6-35b-a3b` at `temperature=0.6` (`prompt_sha256=48d49781...`); re-verify on any prompt update or model change.
